# TPC NavBot: campus information collection checklist

Prepared: 23 October 2026

**Update:** a later school-confirmed submission was received on this date and
selected facts were imported. See [the recorded review and remaining gaps](11_school_confirmed_records.md).
The statement below describes the corpus when this collection checklist was
first prepared; the original generated samples remain unverified.

The current source registry contains 30 generated sample records and zero verified
records. The names below describe topics in those samples; they do not establish
that a facility, program, office, room, or service actually exists at TPC. Ask an
authorized person to confirm, correct, rename, or remove each relevant item.

Start with the Registrar, library, Guidance Office, real classrooms, and the
entrances students use. A small set of complete, reviewed records is enough to
begin answering useful questions. The remaining topics can follow later.

## 1. Information to collect for every destination

| Check | Ask TPC personnel for |
|---|---|
| [ ] Exists and is current | Does this office/facility exist, and is it currently operating? |
| [ ] Official name | Exact office, building, department, or facility name. |
| [ ] Common names | Approved abbreviations and names students use in English, Bisaya, and Tagalog. |
| [ ] Exact location | Building name/code, floor, room number, wing, entrance, and a clear location description. |
| [ ] Room identity | Actual room label and purpose; identify the building when room numbers repeat. |
| [ ] Public services | What students can do there, and which office handles each request. |
| [ ] Service schedule | Days, opening/closing times, lunch closures, appointment rules, and schedule exceptions. |
| [ ] Public contact | Official office phone, email, website, or approved public contact channel. |
| [ ] Access restrictions | Whether students may enter, whether permission/appointments are required, and areas excluded from public navigation. |
| [ ] Accessibility | Separately checked entrances, ramps, elevators, stairs, accessible toilets, and known route barriers. |
| [ ] Official evidence | A current directory, map, notice, handbook, office record, or authorized written confirmation supporting the supplied facts. |
| [ ] Review | Reviewer name, position/office, confirmation date, and permission to include the relevant public information in NavBot. |

First confirm the college's official name, campus address, campus/site names,
building identifiers, entrance names, and the floor-numbering convention. Do not
reuse the sample address or labels such as "Main Gate 1" without confirmation.

## 3. Directions need a separate review

For each route you want NavBot to answer, collect the following separately from
the destination's location record:

- [ ] Exact starting point and its approved alternate names.
- [ ] Exact destination, including building and room where applicable.
- [ ] Ordered walking directions checked on campus with authorized personnel.
- [ ] Confirmed landmarks and entrances along that route.
- [ ] Any restricted passages, closed gates, opening-hour limits, or temporary obstructions.
- [ ] A checked accessible alternative, if available; record barriers explicitly.
- [ ] Approximate walking time only if measured/verified; record the method and conditions.
- [ ] Approximate distance only if measured/verified; record the method.
- [ ] Reviewed English, Bisaya, and Tagalog instructions for the languages you want to support.
- [ ] Source/reference, reviewer, and review date for that specific route.

A route from one entrance does not establish a route from another. Do not assume
every student starts at the main gate. A verified location can be published while
directions, timings, distance, or accessibility remain unavailable.

- [ ] **Research / development / extension office:** sample 15 names an

  scholarship/subsidy inquiries, replacement IDs, payment, and records requests.
  Record referrals explicitly so students reach the correct office.

## 6. What to bring back for integration

Return the completed records and supporting official documents or authorized
written confirmations. If no official map is available, an authorized written
location/route record can support the relevant facts. Keep private student,
patient, counseling, account, and personnel records out of the collection.

The project maintainer can then create new source files, record the genuine
review metadata, compute the required file hashes, and re-index the approved
records. Personnel do not need to prepare JSON or calculate hashes. Leave the
original generated samples unverified; do not approve them as a shortcut.

You do not need to reproduce all 30 samples or retain their equipment lists,
capacities, program claims, or technical details. Collect the smaller set of facts
TPC wants NavBot to publish, and omit unsupported or unnecessary sample content.

See [the source verification workflow](09_source_verification.md) for the
implementation details.
